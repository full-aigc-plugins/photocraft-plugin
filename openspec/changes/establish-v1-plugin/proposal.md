## Why

PhotoCraft 需要将“保留图层的图像编辑与平面设计”落为可独立安装、可追溯、可恢复的 Agent 插件。已安装的上游 CLI 仅证明运行时可用，不能替代技能、Harness 与原生交付验收。

## What Changes

- 建立独立 `photocraft-skills` 的发布与插件锁定引用规范；本变更不把技能源码改成插件私有内容。
- 定义运行时安装、能力探测、任务执行、工程与素材交付、质量修订和宿主发布门禁。
- 固化代表性验收：用产品图制作海报与封面；重开 .pcraft 后文字、产品、背景仍可独立编辑；适用时输出经验证的 PSD。
- 交付中英文产品文档、架构、技术方案与 README；实现按任务与证据逐项推进。
- 2026-10-08 增量：统一公开入口的计划预检与结果语义，收紧技能路由并保留单技能自包含安装；补齐持久化查询、核对、资源预算、摘要绑定评估和对象级受限修订。
- 补充递归图层、文字布局、蒙版保护、逐功能 PSD 验收及复杂变体／滤镜边界；将候选、固定安装、真实宿主路由和逐命令证据分层，建立当前发行身份一致性门禁。

## Capabilities

### New Capabilities

- `skills-distribution`: 独立技能与不可变分发。
- `runtime-distribution`: 运行时安装、能力与回退。
- `task-execution`: 任务状态、幂等、授权与恢复。
- `artifact-delivery`: 原生工程、素材和产物证据。
- `quality-review`: 技术门禁与受限创作修订。
- `release-compatibility`: 宿主、权限与发布验收。
- `domain-workflow`: 保留图层的图像编辑与平面设计。

### Modified Capabilities

无已归档主规格需要另建 delta。本增量继续维护本变更的 ADDED Requirements；当前已存在技能与原生工作流实现，按 Brownfield 保持公开入口、计划和交付兼容性。

## Impact

目标包含独立技能源已有的公开执行脚本与场景资源，以及拟建的插件 `src/harness/`、`src/adapters/`、`src/evaluation/`；实际落点和跨仓职责见 design。插件只消费不可变技能源副本，公共协议仍引用 ArtCraft 权威版本。四款上游应用保留各自工程格式；ArtCraft Services 仅作为架构参考，不复制其受限许可代码。

## Non-goals

用户已授权进入五插件及独立技能实施；本阶段不分发 GUI 应用、不接入真实付费生成，未完成宿主与创作验收前不发布市场条目。协议内容属于目标设计，不能当作现有工具。

## Optimization scope — 2026-10-08

本次授权仅落盘优化规范、设计与任务，不执行安装、编辑实现、发布、主规格同步或归档。上段保留初始范围记录；后续已记录的桌面入口及固定发行证据按现有 PC-DS-001 与 tasks 核对，本增量不新增平台支持或真实付费链路。

借鉴 Dreamina 的职责划分、持久化意图、能力摘要、评估回执和受限修订原则；不照搬其云端登录、积分报价、submitId 查询及图像单轮控制器范围。已有已关闭任务保持原证据边界，新要求与细化任务全部未完成。规范事实源只保留本变更，不在独立技能仓库另建重复 OpenSpec。

## Implementation continuation — 2026-10-08

后续用户要求完成计划任务，本变更已进入候选实现与分层验证；先前“仅规范／文档”描述保留为规划阶段历史。当前实现与限制见 [候选说明](../../../docs/PhotoCraft-Harness-Candidate.zh_CN.md)。独立技能源与插件各自保留事实源，固定快照仅通过后续不可变发行同步。
