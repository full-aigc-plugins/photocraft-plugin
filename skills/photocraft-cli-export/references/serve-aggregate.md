# serve 批量逐步确认

PC-TX-005／9.6 的源 dev.53、插件 dev.68 增量。stdio 与 TCP 的 `batch` 在同一个固定 craft.5 会话内拆成原生单步调用。整个请求先完成严格预检；超过原生 1 MiB 外层帧或任意后续步骤静态无效时，不安装、不启动、不创建输出。

每一步严格校验身份、包络和工具语义，计入累计响应预算后才追加 reply_validated 回执并执行下一步。保留原生 `{completed,failed,results}` 健康输出和原客户端复合／缺省 ID。总截止时间不随步骤重置；累计结果保留原生 8 MiB 预算及请求 ID／包络余量。

保存后的畸形回复或内层错误立即停止。原请求、当前子请求、零基 stepIndex、confirmedSteps 和已验证子回执保留，不返回整批成功，不重放。`stopOnError:false` 不能绕过已声明的失败停止／unknown 核对合同；此前外层监督也拒绝失败批次，本次把停止点提前到下一步编辑之前。TCP 在同一共享锁下执行整批和交付，失败后所有连接隔离；已保存工程和源文件保全，不声称回滚。

测试覆盖两个传输的真实中间原生错误、各七类实际保存后回复故障、累计预算拒绝及健康混合命令／文档／PNG 输出。候选和公开固定安装证据分别记录。MCP command_batch、命令计划中的聚合工具、完整入口输入矩阵及完整 9.6 仍需各自验收；本增量不关闭任务。
