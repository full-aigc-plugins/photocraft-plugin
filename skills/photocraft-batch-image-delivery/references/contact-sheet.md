# 可编辑照片联系表

用于摄影选片、素材盘点和客户审阅：每张图片保留独立的嵌入智能对象，文件名保持为可编辑文字。输入顺序由Agent明确列出，逐行排列；默认3列×2行、240×200像素单元，超过6张自动生成下一张联系表。不裁切、不拉伸、不自动放大，不把它当作高分辨率印刷交付。

## 原生CLI执行

先逐张查看素材方向、尺寸与色彩；明确选片顺序，不递归扫描目录。默认字体对中文可能缺字，先用包含最长文件名、中文和横竖图的样页查看，缺字时在编辑器选可用字体后重新生成或调整。不能只看退出码。

```bash
python3 <本技能目录>/scripts/contact_sheet.py \
  --cli <photocraft-cli实际路径> --output <新的输出目录> \
  --columns 3 --rows 2 --cell-width 240 --cell-height 200 \
  <图片1> <图片2> <图片3>
```

参数作为独立argv传递，路径含空格或中文时使用当前shell的正常引号。输出目录必须不存在；允许1..200张图、1..4列和1..3行，顺序包括显式重复的图片。脚本不改原图，记录原始摘要；工程、预览和manifest.json保存在输出目录。任意一步失败时目录可能保留草稿和命令日志，不能当作完成的交付；修复问题后使用新目录重新执行。

## 方法和参数映射

1. `photocraft-cli info <图片>`读取真实宽高，以单元内可用宽`cellWidth-32`、高`cellHeight-64`计算`scale=min(可用宽/原宽,可用高/原高,1)*100`。
2. `run --new {"width":720,"height":400,"background":"#ffffff"}`建立页面。每页最多12张，避免一次传递数百条命令超过Windows命令行长度。
3. `file.placeEmbedded {"path":"<图片绝对路径>","scale":<百分比>,"fit":false,"smartObject":true,"center":[<格中心x>,<图像中心y>]}`。显式fit=false防止偏好设置改变缩放规则，smartObject=true保留嵌入内容。横竖图使用同一比例，检查返回bounds在格内。
4. `type.create {"x":<格中心x>,"y":<图片下方基线>,"text":"<完整文件名>","name":"Caption: <完整文件名>","size":12,"color":"#000000","align":"center"}`。y是文字基线。脚本核对实际文字bounds宽度，标签超出格宽则拒绝交付并保留草稿，不能偷偷截断文件名。
5. `--out sheet-001.pcraft`保存分层工程；`convert`导出PNG；再次`info`读取保存后的工程，核对图层数量为`1+2*本页图片数`。原图sha256前后应一致。

## 同画面MCP执行

使用photocraft-editor技能建立当前任务的已就绪会话，再按实际schema用doc_new建立页面，command_run依次包装上面的file.placeEmbedded和type.create。图片路径应位于该会话允许读取的工作区；坐标、百分比、文字与原生版本相同，但文档索引和对象ID必须取当前返回值。doc_inspect检查图层与画布，doc_save另存工程，doc_export导出PNG；不要在原生无界面引擎生成后声称已经同画面同步。

## 查看与验收

逐页检查横竖比例、图片未裁切、文字未覆盖照片、标签对应文件及分页总数。打印用途另核对像素、DPI、ICC和最终尺寸；当前脚本不管理ICC或保证打印色彩。透明PNG可能在白底合成，需查看边缘；EXIF方向与字体缺字不能由数量检查证明正确。保留分层.pcraft、PNG和manifest，输入原图保持不变。

已实测原生0.9.0 macOS：7个显式输入（3种合成横竖/方图重复排列）生成2页，分别13层与3层，保存后读取通过，导出PNG可查看。不是7种真实照片，尚无Windows、全部字体/格式或真实宿主同步验收。本流程扩展既有批量交付技能，暂不增加已登记的232条场景计数。
