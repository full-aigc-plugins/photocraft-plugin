# 流式启动配置预检

PC-TX-005 的安装前校验覆盖公开 `cli.py mcp` 与 `cli.py serve` stdio 的启动配置。无效目录、缺少已识别选项的值、bridge 非 loopback 地址及缺失／无效／冲突凭据，在读取第一条请求和调用安装器前返回结构化 validation 错误。错误只含稳定代码与字段位置，不回显凭据或文件正文；不创建令牌文件。

```mermaid
flowchart LR
    A[原生启动参数] --> B[只读启动预检]
    B -->|无效| C[not_executed 零安装零进程]
    B -->|有效| D[逐条请求预检]
    D --> E[首个有效请求安装并启动一次]
    E --> F[同一会话执行并核验回复]
    F -->|有效下一请求| D
    F -->|未知或失败| G[停止后续编辑 不重放]
```

兼容固定原生 Args：`--key=value` 和分开的值、最后一次赋值、原生忽略的选项／位置参数及 `--help` 保留。只检查当前模式生效的配置：headless MCP／serve stdio 检查目录；bridge MCP 检查地址和客户端凭据，忽略 headless 根；非 bridge 的凭据选项保持原生忽略行为。CLI 值优先于对应环境值，不抹掉另一个凭据环境变量造成的冲突。合法目录符号链接与相对目录保留，不展开原生不支持的 `~`。

目录访问能力及实际连接仍由原生在使用时确认，预检不能证明未来目录不变化、端口可连接或令牌被服务端接受。TCP 的既有启动校验保持独立。

同一输入流内的创建、编辑、保存、检查共用一个原生进程，不按命令重启。真实原生测试记录每个协议只启动一个进程，并在结束后收束；不启动 GUI。桌面自有会话的跨调用复用尚未由本增量实现，也不声称 FilmCraft 已修复。9.6 完整输入矩阵、共享桌面写入及全部 V1 验收继续开放。

测试：`tests/test_stream_launch.py` 覆盖13个独立技能、208个公开启动负例、读取输入前拒绝、合法旧选项及两种真实协议的同会话原生保存。真实测试需显式设置 `CRAFT_NATIVE_COMMANDS=1` 和隔离的 `CRAFT_RUNTIME_HOME`。
